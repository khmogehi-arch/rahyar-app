# راهیار — MVP

پیاده‌سازی فاز ۱ راهیار طبق «سند مشخصات فنی پیاده‌سازی — راهیار MVP»: مسیریابی گام‌به‌گام داخل
ساختمان با یک اسکن QR در ورودی، بدون موقعیت‌یابی زنده و بدون وابستگی به هیچ پلتفرم IPS (مثل
Situm/Mapxus). این پروژه دقیقاً طبق بخش ۷ آن سند («خارج از دامنه») ساخته شده و هیچ‌کدام از موارد
زیر را ندارد:

- موقعیت‌یابی زنده / نقطه آبی متحرک
- یکپارچه‌سازی با SDK سیتوم، Mapxus یا هر پلتفرم IPS دیگر
- واقعیت افزوده (AR)
- اپ نیتیو iOS/Android
- نقش‌های کاربری پیچیده یا چندسطحی (فقط یک سطح دسترسی کارمند)

## ساختار پروژه

سه بخش، روی یک بک‌اند مشترک و یک پایگاه داده یکسان:

```
backend/        API واحد (Express + SQLite) — هر دو اپ از آن استفاده می‌کنند
admin-panel/    اپ الف: پنل داخلی تیم (React, وب مرورگر دسکتاپ)
visitor-app/    اپ ب: وب‌اپ مراجعه‌کننده (React, PWA-ready, موبایل)
```

مدل داده طبق بخش ۳ سند: `Building`, `Floor`, `Node` (ورودی/مقصد/تقاطع/آسانسور), `Edge` (یال
جهت‌دار با فاصله واقعی و دستورالعمل), `QRCode`, `Beacon`, `Destination`.

## راه‌اندازی برای توسعه

### ۱. بک‌اند

```bash
cd backend
npm install
cp .env.example .env      # مقادیر JWT_SECRET و ADMIN_PASSWORD را عوض کنید
npm run seed              # ساخت کاربر کارمند اولیه (رمز عبور ساده)
npm run dev                # http://localhost:4000
```

### ۲. پنل داخلی تیم (اپ الف)

```bash
cd admin-panel
npm install
cp .env.example .env
npm run dev                # http://localhost:5173
```

با نام کاربری/رمز عبور تعریف‌شده در `backend/.env` وارد شوید. سپس به ترتیب: ساختمان و طبقه
بسازید، پلان طبقه را آپلود و مقیاس‌بندی کنید (کلیک دو نقطه با فاصله واقعی معلوم)، در «ویرایشگر
نقشه» نقاط (Node) و یال‌ها (Edge) را ترسیم کنید، برای نقاط ورودی کد QR بسازید، و مقاصد را برای
نمایش در اپ مراجعه‌کننده ثبت کنید.

### ۳. وب‌اپ مراجعه‌کننده (اپ ب)

```bash
cd visitor-app
npm install
cp .env.example .env
npm run dev                # http://localhost:5174
```

آدرس هر کد QR تولیدشده در پنل داخلی چیزی شبیه `http://localhost:5174/entry/<token>` است — دقیقاً
همانی که مراجعه‌کننده با اسکن QR درب ورودی باز می‌کند. صفحه اول اسکن را resolve می‌کند، سپس صفحه
انتخاب مقصد و در نهایت مسیر گام‌به‌گام (محاسبه‌شده یک‌باره، بدون رهگیری زنده) نمایش داده می‌شود.
دکمه «مسیر را گم کردم» کاربر را به انتخاب مقصد بازمی‌گرداند.

## نکات پیاده‌سازی

- **مسیریابی**: الگوریتم Dijkstra ساده روی گراف Node/Edge، فقط در لحظه انتخاب مقصد اجرا می‌شود
  (`backend/src/utils/dijkstra.js`) — بدون GPS، بلوتوث یا هیچ درخواست دسترسی موقعیت مکانی.
- **بیکن**: صفحه «بیکن‌ها» در پنل داخلی صرفاً ثبت UUID/Major/Minor در دیتابیس و اتصال آن به نقطه
  آسانسور است؛ هیچ اسکن BLE یا موقعیت‌یابی زنده‌ای در کد پیاده‌سازی نشده (طبق بخش ۷، این ویژگی
  عمداً کنار گذاشته شده).
- **احراز هویت**: ورود ساده با رمز عبور برای کارکنان (JWT)، بدون نقش‌های چندسطحی. وب‌اپ
  مراجعه‌کننده اصلاً فرم ورود ندارد — فقط با اسکن QR باز می‌شود.
- **PWA**: وب‌اپ مراجعه‌کننده دارای `manifest.json` و آیکون است و از طریق «Add to Home Screen» در
  مرورگر قابل نصب است؛ به SDK یا مجوز موقعیت‌یابی نیازی ندارد.
- **پایگاه داده**: SQLite (فایل محلی) — مناسب حجم داده کم فاز ۱؛ مهاجرت به PostgreSQL در آینده با
  تغییر لایه دیتابیس (`backend/src/db.js`) امکان‌پذیر است.

- [x] اپ مراجعه‌کننده بدون نصب، فقط با اسکن QR باز می‌شود.

- [x] پنل داخلی امکان افزودن یک ساختمان کامل (پلان، Node، Edge، QR) را از ابتدا تا انتها فراهم
      می‌کند.
- [x] دکمه «مسیر را گم کردم» کار می‌کند.
- [x] کد به تفکیک صفحه/کامپوننت ساختاریافته تا در فاز ۲ (React Native) قابل استفاده مجدد باشد.
